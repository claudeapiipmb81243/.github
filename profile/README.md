<p>付款之前的那十几分钟，几乎决定了后面几个月是省心还是糟心。多数纠纷不是因为产品不行，而是因为双方对"独享""稳定""随时替换"这些词的理解从一开始就不一样。这篇把下单前该问的问题整理成一张可以照着念的清单：资质与资源、试用与验收、替换与退款、售后响应四段，每段给出什么叫合格回答、什么是不合格信号，以及怎么用一次小测试把答案验证掉。</p>

<h2>一、清单的第一段：资质与资源，四个必答项</h2>
<p>这一段决定你买到的到底是不是你以为的东西。回答得越具体，后面越省事；一旦开始绕，就说明对方自己也没把握。</p>
<h3>ASN 与地址归属能不能给出</h3>
<p>要求提供地址对应的 ASN 编号和注册机构名称，自己用公开查询入口核对一遍。ASN 挂在住宅宽带运营商名下，才算方向对；挂在机房或云厂商名下，无论怎么解释，都不属于住宅出口。</p>
<h3>同池客户数与并发上限是多少</h3>
<p>这两个数字直接决定你实际拿到多少资源。合格回答是给出具体上限并愿意写进订单；不合格回答是"很多人在用但很稳定"这类无法量化的描述。</p>
<h3>地址会不会在租期内变化</h3>
<p>长期业务最怕地址悄悄漂移。要问清：正常情况下的最短保留期是多久，什么条件下会触发更换，更换前是否通知。把"最短保留期"写进合同，比任何口头保证都有用。</p>

<h2>二、清单的第二段：试用怎么设，才测得出结论</h2>
<p>试用最容易走过场：给了两小时，插上能通，就下单了。有效的试用必须覆盖你的真实使用时段和真实请求特征，否则测了等于没测。</p>
<h3>试用时长要跨过一个晚高峰</h3>
<p>至少 24 小时，必须包含你业务的高峰时段。跨境线路的差异主要出现在晚间，白天测出来的数据基本没有参考价值。如果对方只肯给两小时，就把它当作连通性检查，不要当性能结论。</p>
<h3>试用要跑真实请求而不是 ping</h3>
<p>用你实际要调用的接口、实际的请求体、实际的并发，连续跑一段时间，记录成功率、P95 耗时和重试率三个指标。只 ping 出口地址，测不到代理层的排队、鉴权和长连接回收问题。</p>

<h2>三、清单的第三段：替换和退款，别只听口头承诺</h2>
<p>这两项是纠纷高发区。不是因为供应商都赖账，而是因为"免费替换"这四个字没有定义：换几次算免费、多久生效、换完还是不是同类地址，每条都能吵起来。</p>
<h3>替换规则要写成四句话</h3>
<p>一个月内免费替换几次、提交后多久生效、替换后是否保证仍是同类型地址、因质量问题替换是否计入次数。四句话写在订单备注或聊天记录里，出问题时才有依据。</p>
<h3>退款条款看的是触发条件</h3>
<p>常见的可退情形包括：地址类型与描述不符、长期不可用、无法按约定提供服务。要问清判定标准由谁认定、需要提供什么证据、退款周期多长。模糊的"不满意可退"在实际执行中往往很难。</p>

<h2>四、清单的第四段：售后响应，用三个场景去验证</h2>
<p>售后能力在付款前也能测出来：问三个具体场景，看对方回复的速度和具体程度。能说清流程的，通常真处理过；只会说"联系我们"的，故障时大概率也是这句话。</p>
<h3>场景一：晚高峰大面积超时</h3>
<p>问：如果晚上八点到十点出现批量超时，你们怎么定位、多久给结论、会不会先给备用线路。合格回答会提到分段排查和临时切换，而不是直接让你"重启试试"。</p>
<h3>场景二：地址被标记或类型不符</h3>
<p>问：如果自查发现地址类型被人重新归类，走什么流程、要不要费用、多久换好。这个问题能顺带验证对方是否真的会做类型复核。</p>
<h3>场景三：账单与用量对不上</h3>
<p>问：流量统计以哪一侧为准，误差范围多少，能否提供明细导出。接口调用量大的团队，早晚会遇到对账问题，提前问清比事后争论省力。</p>

<h2>五、把清单收成一张评分表，别凭感觉拍板</h2>
<p>问完之后，把答案按可验证程度打分，比"感觉这家还行"可靠得多。评分不需要复杂，四段各给一个通过或不通过，两项不通过就换下一家。</p>
<h3>评分只看可核实的部分</h3>
<p>能自己查的（ASN、类型标签、公开黑名单）权重最高，因为不依赖对方表述；能写进合同的次之；只能口头承诺的最低。这个排序能有效过滤掉话术漂亮的方案。</p>
<h3>先小额、短周期起步</h3>
<p>即使评分很高，也建议先买最小规格、最短周期，跑满一个完整周期再续。一个周期里至少会经历一次高峰、一次波动，这些是纸面参数看不出来的。</p>

<h2>常见问答</h2>
<h3>对方不肯给 ASN，是不是一定有问题？</h3>
<p>答：不一定，但风险偏高。有些转售商自己也不掌握上游信息，只能说个大概。这种情况下可以退一步：要求提供一条测试地址，自己查 ASN 和类型标签，用实测结果代替对方的口头说明。</p>
<h3>试用期表现好，正式用会不会变差？</h3>
<p>答：有可能，尤其是共享类资源。试用期用户少、负载低，正式使用后同池人数增加，表现会下滑。降低这个风险的办法是问清同池客户数上限，并在合同里约定资源不缩水。</p>
<h3>按月付还是按年付更划算？</h3>
<p>答：新供应商先按月，跑满一个完整计费周期、经历过一次高峰和一次替换，再考虑更长周期。年付的折扣往往换来锁定期，线路质量下滑时退不出来的部分比省下的多。</p>
<h3>售后响应时间写进合同有意义吗？</h3>
<p>答：有，但要配套约定违约处理。只写"2 小时响应"而没有对应措施的条款，执行力度有限。更实际的做法是把响应时效和替换、补偿挂钩，形成可执行的约束。</p>
